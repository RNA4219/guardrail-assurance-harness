# ADR 0002: GAH独自の評価契約と判定境界

## 背景

二つの利用場面、WARNINGのCI成功、初期数値、生成AIによる管理が確認済み。要求から実装へ進むため、採択・実行・観測・判定・保存・CIを区別する必要がある。[Task](../tasks/TASK.contract-design-09-10-2026.md)で設計初版を作成した。

## 判断

- GAHの要求から独立して契約を定義する。既存外部資産の抽出や移植を前提にしない。
- 管理AIが構造化された採択を要求し、認証済みの管理境界が初期方針と固定検査で適用する。通常更新には都度の人間承認を置かない。
- 不変の契約/観測/判定と、世代付きの採択参照を分ける。実行中や完了したrunの契約を差し替えない。
- Assuranceと実行/出力完了を別に保持し、CIは期待bindingも照合する。終了コード案は0=成功、1=完了した不合格等、2=実行不成立、3=取消し。
- 率は分数で表す。費用は元の精度を保持し、予算比較用には操作総額を整数のUSD百万分の一へ切り上げる。

## 代替案と影響

AIの自由文だけを採択根拠にする案は、認証・変更範囲・再現性を検査できないため採用しない。AssuranceだけでCIを成功にする案は、別目的や保存失敗を成功にするため採用しない。共通coreを先に分離する案は、境界の妥当性と利用側が未検証のため見送る。

この判断で必要になる正式Schema、保存の原子性、認証・隔離、adapter版の確認は次の実装準備事項。[設計](../design.md)と[契約](../contracts/evaluation-contract.md)を正本とし、具体のデータベースや外部libraryを本ADRで選定しない。

## 2026-09-11の補正

[設計の見直し](../reviews/design-review-20260911.md)により、不変のreceiptと現在のUseDecision、成功前の精算、資源別予算、キャッシュの参照記録、一セッション一分類を追加した。元の要求・初期値と通常更新のAI管理方針は維持する。

## 状態

v0.3では[複合条件のレビュー](../reviews/state-review-20260911.md)から、配布BootstrapContract、採択確定時の権限/証拠検査、runの所有世代、停止期間を含むdeadline、微小課金の切上げ、保存/送信前の境界、保存障害と取消しの優先順を追加した。最小金額を切り捨てる案、旧workerを無条件に信用する案、取消しで保存失敗を隠す案は、既存要求を満たせないため採用しない。方式・実環境検証は未完了。
