# 外部参照元の参照境界とGAHの独立設計

## 現行方針

2026-09-10の利用者訂正「外部参照元自体はクローズド資産なんでそのまま使わないでね」を適用する。外部参照元は一般的な運用上の考え方を参考にする対象であり、GAHへ移植する資産ではない。以前の「転用対応表」「移植設計」の方針を取り消す。文書pathは既存参照のため維持するが、現在の指示は本書の参照境界である。

外部参照元のコード、Schema、テスト、文書、データをGAHへ複製・移植・依存化・同梱しない。名前やフィールドを置き換えただけの移植も行わない。GAHの仕様・データ契約・fixture・テスト・実装は、[要求](requirements.md)と[受入条件](acceptance-criteria.md)から独立に作成する。

外部参照元に含まれる、または関連する第三者OSSを利用する場合は、そのOSSの公式配布元・仕様・ライセンスを別に確認し、外部参照元経由でコードを取り出さない。外部参照元本体の公開化・ライセンス変更を要求せず、GAHの着手条件にもしない。

## GAHの要求から設計する事項

以下は一般的な設計上の観点とGAHの要求の対応であり、外部参照元の関数・Schema・試験ケースの移植一覧ではない。

| 一般的な観点 | GAHで定義する内容 | 要求と受入 |
|---|---|---|
| 評価開始前の入力検査 | Control・評価契約・対象内容・予定義務の妥当性 | R01/R02、AC01/AC02 |
| 進捗と結果の整合 | run/対象/契約/試行の結び付け、重複・取消し・遅延結果 | R05/R18/R26、同番号のAC |
| 判定の理由を残す | GAHの五状態、Critical優先、WARNING成功、鮮度・予算 | R04/R12/R13/R19、同番号のAC |
| 履歴を保つ | 採択済み証拠の不変性、並行更新・途中失敗・失効 | R18/R22/R26、同番号のAC |
| 基準と候補を分ける | 内容識別子・採択権限・試行/世代・セッションの分離 | R24〜R26/R30/R31、同番号のAC |
| 契約と受入を対応させる | GAH固有の正常・境界・欠損・矛盾のfixtureと人間/機械向け出力 | R01/R02/R19/R23、同番号のAC |

GAHの指標計測・比較・校正・評価データもGAHの要求から設計する。外部参照元の運用実績やPASSをGAHの証拠へ継承しない。二つの利用場面、32要求/32受入条件、[初期運用方針](operating-policy.md)の数値と生成AIによる管理は維持する。
