# 未決定事項と今回の明確化

[要求明確化案v0.1](requirements.md)で振る舞いを具体化した。すべての論点を利用者判断待ちにせず、要求で決めること・運用で選ぶこと・設計で決めることに分ける。要求案の採択と実装はまだ行っていない。

## 利用目的・運用の確認事項

| ID | 判断事項 | 現在の案 | 影響 |
|---|---|---|---|
| GAH-D01 | 最初の利用場面 | 仮定A01: coding agentの開発・CI | 優先するControl、adapter、評価データ |
| GAH-D02 | 標準CIでWARNINGを許すか | HEALTHYだけ成功。WARNINGも不合格 | CI運用の厳しさ。CriticalのHOLDは緩めない |
| GAH-D03 | 利用目的ごとの基準・閾値・予算 | 実行前に設定必須。原稿の仮値は本番既定値にしない | 対象組織のリスク受容と合格水準 |
| GAH-D04 | 初回の比較基準と評価データ | baseline候補を別目的で作り、ownerが選定・固定 | 比較の信頼性と適用範囲 |

これらの回答前でも、原稿との対応と受入条件の整理は進められる。仮定を人間の承認済み事項と記録しない。

## 前回の12論点の処遇

| 元ID | 要求段階で明確化した内容 | 残る工程 |
|---|---|---|
| GAH-Q01 | MVP4機能と必須の支援機能、本番段階展開などの後期対象を分離 | 要求案の採否 |
| GAH-Q02 | ID、owner、必要検査、依存の妥当性をGAH-R01で要求 | invariantの具体記法・Schemaは設計 |
| GAH-Q03 | 結果の意味、Assuranceの優先順、HOLD解除、CI返却を§5・§7へ | GAH-D02、具体の状態APIは設計 |
| GAH-Q04 | 計数、0分母、ERROR、除外、coverage分母を§5・§6へ | 合成fixture・oracleの具体化 |
| GAH-Q05 | 比較条件、意図した変更軸、未設定と計算不能を§6へ | GAH-D03、GAH-D04 |
| GAH-Q06 | 外部参照元抽出をMVP着手の必須前提から分離 | 現物確認後に再利用範囲を設計。外部参照元は未変更 |
