# 拡張要件の反例レビュー

対象は[MVP後の拡張要件 v1](../productization-requirements.md)。Codexが要件を読み、受入を誤って通せる反例を点検して本文へ反映した。独立した外部監査・モデル委任・製品試験を行った記録ではない。

| 反例・不足 | 反映した要件 | 要件上の補正 |
|---|---|---|
| 自作fixtureだけで実案件に有効と言える | PR01〜04 | 外部の許可済みrepoを最低1つ含め、実履歴・検査用変更・実利用入力を分離。実劣化が取れない場合は未実証 |
| 自分で付けた正解へ調整し続ける | PR02〜03、14 | 期待結果と受入集合を候補から独立に固定。事後変更は版を分け、元の失敗を残す |
| 正常ラベル不明の行を捨てて誤警報率を下げる | PR02〜03 | 独立した正常100件を必要とし、不明を分母に含めない。不足は未受入、重複で水増ししない |
| 全体の平均だけ良くして必須カテゴリの劣化を隠す | PR02〜03、13 | 適用Control・カテゴリ別に結果を保持し、既存の最小標本とCritical条件を維持 |
| 低品質な評価対象だからharnessまで受入失敗にする | PR03 | 正しい劣化判定も受入成功になり得る。対象をHEALTHYに調整することを完成条件にしない |
| 複合工程9993秒を通常runのbaselineに流用する | PR05〜06 | 通常runの区間を別に固定し、同一条件で基準版を新測定。受入済み履歴の意味を変えない |
| 12runnerで時間を短縮し、費用増を隠す | PR05〜08 | wall time・総runner時間・CPU/RSSと共通/追加テストの費用を分離、既存資源上限を維持 |
| deep copy呼出数だけ減らし、別の全走査へ置換する | PR07 | copyだけでなく走査・直列化の仕事量を計数。件数と履歴の増加、page上限も検査 |
| warm cacheだけで測り、失効もcacheしてしまう | PR05〜07 | coldとwarmを事前固定し、撤回/更新/削除/再起動後の現在利用を再検査 |
| 速い一部のCI、古いSHA、取消しjobを全件合格にする | PR08、13 | fullの全件集約と対象SHAを維持し、skip/cancel/未起動を成功にしない |
| 3回の中央値を運用上のp95として売り出す | PR05〜07 | fullの中央値/最大と照会100回の観測p95を区別。一般分布の保証へ広げない |
| 前提導入や後始末を時間から消し、30分導入と言う | PR06、09 | 計測区間を固定し、通常runの停止・回収・精算を含める。導入総時間と前提導入済みの時間を併記 |
| doctorが時計同期を止めたり権限を広げてPASSにする | PR10、12 | 診断と環境修復を分離し、既存の時計・権限条件を維持。未知環境は未対応 |
| sampleが既存データを初期化し、同一identityで採択する | PR09、12、14 | 新規workspace、再実行の冪等性、所有範囲、管理AIの権限分離を受入条件化 |
| 保守工数だけ減らしてモデル呼出数や人間介入を増やす | PR04 | 対応観測で時間・資源・介入を同時評価。既存手順がなければ削減を実証済みにしない |
| 文書のapprovedを新機能の完成と読む | PR14、完了境界 | 文書、技術受入、有用性、全体受入、公開を分離。新14条件は全てNOT_RUN |

残る不確実性は、利用許可を確認できるpilot対象と期待結果、同一環境での処理負荷内訳、提案SLOの達成可能性。M0で実値を固定する。数値に届かなければ原因と追加案を記録し、結果後に合格ラインを緩めて成功へ書き換えない。

既存のGAH-EX01は実利用集合、EX03は正常タスク達成率の観測まで今回に具体化した。全集合更新・閾値探索・長期drift等の未採択部分は保持する。管理主体を生成AIとする決定と、通常運用での都度人間承認不要の範囲を維持する。
