# 運用方針の決定と要求v0.4への反映

## 決定と範囲

利用者の回答「CIで許す」「閾値と予算はおまかせ」「評価周りはopsのOSSから転用」「管理主体は生成AI」に基づく文書改訂。[v0.3保存稿](../research/archive/before-operating-decisions-20260910/docs/requirements.md)から、32要求と32受入条件のIDを維持して[初期運用方針](../operating-policy.md)を加えた。

WARNINGのCI成功と生成AIの管理主体は利用者決定。数値は委任に基づくCodexの選定で、実測から推定した水準ではない。文書metadataのownerは資料の管理情報であり、製品の基準管理を人間へ戻す意味ではない。通常の基準採択に都度の人間承認を置かず、管理AIの構造化要求を権限・根拠・固定条件で検査する。

## 初期値の選定理由

| 選定 | 理由と適用限界 |
|---|---|
| 非Criticalの検出率95%以上、FPR5%以下、検出率低下2ポイントまで | 固定した合成集合で絶対水準と回帰を別々に検査する初期値。正常側の改善で見逃し増加を相殺しない |
| Criticalの検出率99%以上、FPR2%以下、Mutation Score100% | Criticalのカテゴリには厳しい集計基準を適用。各事象の禁止条件は一件でも違反として別に扱う |
| 全体で要検知200・正常200以上、カテゴリの適用群各100以上 | 少数の算術例を運用集合と取り違えない最初の規模。独立性や母集団精度を件数だけで保証しない |
| PR20分・USD 2、全対象90分・USD 10、直近24時間USD 20 | 小さい変更での評価と全対象評価を区別し、run分割・並行予約・管理AI処理も合算する。実測の速度保証ではない |
| 現在の証拠24時間、baseline比較証拠30日 | 古い結果を無期限に使わない初期期限。版変更や失効は期限内でも再確認する |
| 有限集合を既定、母集団推定は無効 | 転用元の評価手法を確認する前に統計手法や信頼水準を既成事実にしない |

全値・単位・境界・予約・例外の正本は運用方針に置く。基準管理AIはその範囲内で厳格化・更新できるが、初期値より弱い閾値や必須義務の削除を通常更新で採択しない。既知の違反と旧契約の評価結果は保持する。

## DGX Qwenの指摘と処遇

既存のDGX接続を通じてqwen3.8-flash-nextへ初期方針の文書照合を1回依頼した。対象は下書きの整合性のみ。4指摘を親が原文へ照合した。

| 指摘 | 処遇 | 理由・反映 |
|---|---|---|
| WARNINGの任意項目と予算80%の関係が曖昧 | 明確化 | 予算接近を任意の注意項目と明記。累積予算を対象とし、並列数や一呼出し上限への接近は注意率の対象外にした |
| Mutation Score100%と丸め前判定が矛盾する可能性 | 不採用 | 矛盾しない。丸めて100%と表示されても分子が分母未満ならCriticalの100%条件に違反する。条件は維持 |
| 直近24時間の起点と未解消予約が曖昧 | 採用 | 判断時刻Tの(T−24時間, T]内の確定額と、全未解消予約を合算。古い未完了runを時刻だけで解放しない |
| 転用元未特定と推定手法固定の時系列が曖昧 | 明確化 | 特定後に手法を選定する順序を明記。既定では母集団推定を無効とする方針は元から維持 |

親の追加照合で、管理AIの採択runにも予算を適用すること、子処理を並列数へ含めること、Critical格下げ・必須義務削除を通常更新から除くことを補った。Qwenの回答を製品検査や独立した保証に数えない。

## 転用元と次工程

opsのOSSを転用する方針は確定。正確な名前/pathは照会中。ローカルのops関連候補と元原稿の外部参照元参照を確認したが、同一の転用元と断定できる根拠は得ていない。特定後に固定版、コード/データ別の利用条件、評価runner・結果形式・ケース/ラベル・比較/校正の再利用対応を作る。今回の作業ではコードや評価データを転用していない。

要求の追加検討はここで区切り、契約・評価設計へ進める。Schema、状態API、常設管理AIの実行identity、具体の隔離方式、初回baselineの実データを次工程で定義する。
