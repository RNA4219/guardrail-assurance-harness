# 二つの初期対象を反映した改訂記録

利用者がcoding agentの開発・CIとLLMガードレール評価の両方を指定したため、v0.1の仮定A01を置き換えた。D01のみを確認済みとし、D02の標準CI方針、D03の閾値・予算、D04の評価データ・baselineは運用判断として残す。

## 要求の変更

- UC-CIは通常の制約違反と、Mutationに対する検査系の反応を分離する。
- UC-LLMは期待ラベルを固定し、混同行列・検出率・見逃し率・FPRを表示する。検知と遮断、ASRと見逃し率を混同しない。
- 対象の変更軸と、データ・oracle・反復などの比較条件を分離する。観測差と統計的な確かさも区別する。
- 利用場面別の結果を残し、一方の合格やFPR改善で他方の必須違反を相殺しない。
- 任意の計画補助LLMの不在は許容できるが、対象LLM・必須評価器の失敗は評価欠損として残す。

R01〜R24の番号を維持し、同番号のACと二つの最小シナリオを更新した。算術例はTP=8/FN=2/FP=1/TN=9からTP=6/FN=4/FP=0/TN=10への変化であり、製品実測・本番閾値ではない。
