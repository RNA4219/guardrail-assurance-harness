# 契約・評価設計の照合

[Task](../tasks/TASK.contract-design-09-10-2026.md)で要求v0.4と初期運用方針v1を、GAH独自の論理契約へ具体化した。32要求・受入条件・初期数値は維持する。設計文書と算術の技術検収であり、製品試験・実測ではない。

## DGX Qwenの利用と処遇

利用者が指定したDGX Qwenを既存の接続経由で使用した。送信範囲はGAHの設計・評価契約草案と初期運用方針だけ。最初の照会は応答本文がnullで保存不能。出力設定を調整した二回目は本文を得たが、2200出力tokenの上限で末尾が途切れた。6件目を完了した指摘と扱わず、親が一次の要求本文と照合した。最初のusageは保存できていない。

| Qwenの候補 | 親の検討・処遇 |
|---|---|
| 分母0を100%にする案、全件NO_COVERAGEで分母0という説明 | 不採用。要求§6と矛盾し、NO_COVERAGEは分母に入る。0/0も評価不能と契約に再明記 |
| 初回baseline候補の終了コードが曖昧 | 説明を補強。別目的で比較を事前非適用とする場合のみ0になり得る。通常回帰への代用は1 |
| 停止・終了確認と予約の確定を同時にする案 | 同時化は不採用。終了確認と料金確定を分離し、終了不明時の再試行開始保留、料金未確定予約の保持を明記 |
| baseline_refが常に必須に見える | 採用。比較必須時の参照、初回の明示null・非適用理由、参照未指定と根拠不足の扱いを区別 |
| 循環参照の終了コードが不明 | 既存の入力拒否規則でHOLD/2と決まる。例として明記し、任意の取消しコードへ変えない |
| 24時間の区間境界（途中で打切り） | 完成した指摘として採用しない。初期方針の(T−24時間,T]と全未解消予約を直接照合し、境界例B05へ反映 |

Qwenの出力を独立した保証や最終判定にしない。照会のreceiptと出力hashは[設計検証記録](../evidence/contract-design-20260910/design-check.json)に記録する。

## 親が追加した整理

設計入口の古い共通core抽出案を訂正した。採択の初期方針・認証主体・世代競合、実行中の契約固定、原子的な予算予約、保存後の最終receiptを具体化した。Assuranceと実行状態を分け、43件の設計例と32要求の対応を用意した。

設計初版後の7項目は[判断事項](../open-questions.md)に明示した。正式Schema、保存/認証/隔離方式、外部adapterの公開原典と固定版、ケース/校正の実データ、保持設定はこれから検証する。これらの製品試験を今回の文書検査に含めない。
