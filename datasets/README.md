# 評価データ

[synthetic-policy-v1](synthetic-policy-v1/README.md)に受入400件・校正18件・開発12件の合成入力とoracleを配置した。[評価詳細仕様](../docs/evaluation-detail-spec.md)に意味差、用途分離、段階数、生成器から独立した照合を定める。配布データの生成と実モデルの校正・受入は別に記録する。

UC-CIでは制約・検査系と定義済みMutationの合成fixture、UC-LLMでは要検知/正常の期待ラベル付き合成ケースを今後管理する。共通してケースID、由来・使用条件、版・digest、期待結果とその根拠を保持する。

UC-LLMは期待ラベルを対象ガードレールの今回の回答から作らず、評価前に固定する。カテゴリ、集計単位、反復回数、モデル・評価器設定、校正根拠も比較条件に含める。不明ラベルや応答欠損を正解・正常へ変換しない。

開発・校正・受入の用途と利用履歴、同一/派生ケースのグループを保持する。調整に使った集合を独立した受入データと表示しない。単発と二段階の合成ケースで初期状態・引継ぎ・各段階の期待条件を定義し、反復回数を独立ケース数へ水増ししない。有限集合の回帰確認と母集団の推定は目的を分ける。

外部参照元はクローズド資産であり、[参照境界](../docs/reference-boundary.md)に従って外部参照元のデータ・fixture・期待ラベル・テストを持ち込まない。GAHの合成ケースを要求と受入条件から独立に用意し、由来・利用条件・ラベルと校正根拠を記録する。公開データを使う場合も原典から別に確認する。

[初期運用方針](../docs/operating-policy.md)でUC-LLMの全体は要検知200件以上・正常200件以上、必須カテゴリの適用する正負の群は各100件以上とした。[要求明確化案](../docs/requirements.md)と[受入条件](../docs/acceptance-criteria.md)の算術例をそのまま実データの受入集合にせず、基準管理AIが独立性・由来と必須条件を確認して採択する。
